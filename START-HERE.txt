  C. WATCH THE CHECKS ON GITHUB. Open your repository on GitHub, then
     the Actions tab. A run called Tests starts by itself a few seconds
     after each upload. It has three parts, which run side by side:
        Node tests                     two or three minutes
        Browser tests                  about twenty minutes
        Database (stand-in Supabase)   about five minutes
     If you uploaded in the browser, a run for an earlier drag may show
     as cancelled (grey): each upload stops the run before it, so only
     the finished upload is checked in full. That is expected.
     Done when: the newest Tests run has a green tick.
     A green tick with a yellow warning names a browser check that
     passed only on its second try: nothing is wrong with the shop, but
     mention it with your next request so it can be made steadier.
     A red cross instead: open the run, then the part with the cross.
     The lines with ✗ say which check failed and why. Send me those
     lines, or the whole log (the ⚙ menu on that page > Download log
     archive). The shop is not affected: Netlify publishes as before,
     whatever the checks say.

  D. KNOW WHAT THE CHECKS COST. GitHub counts the minutes they use. A
     public repository uses none. A private one on GitHub's free plan
     has 2,000 minutes a month, and each upload uses about 25
     (the three parts are counted separately), so roughly 70
     uploads a month. When they run out, the checks stop until the
     next month; GitHub only charges if you have set it up to pay for
     more.
     To stop the checks: Actions > Tests (on the left) > the ··· menu >
     Disable workflow. Enable workflow, in the same place, starts them
     again.
     Done when: you know which kind your repository is (GitHub shows
     Private or Public beside its name).

   hour is up. They never fall back to the old way because of a limit.
